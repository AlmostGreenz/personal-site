# Personal website — static source

This is the full source of the static site. The JSON files in `data/` are the
site's database; `build.py` renders them into the deployable site in `docs/`,
which GitHub Pages serves. Live at https://www.ryanbgreen.ca/.

Everything is vendored and CDN-free: fonts, icon fonts, and JS libraries are
local files, and all internal URLs are page-relative (works from `file://`,
localhost, and any repo path).

## Workflow

1. Edit the JSON files in `data/` to update content. Keep Ryan's writing
   verbatim — content changes get drafted and approved before editing.
2. Install dependencies once: `pip install -r requirements.txt`
   (on this VM's Python, add `--break-system-packages`).
3. Rebuild: `python3 build.py` (regenerates `docs/`).
4. Extract the build over the repo at
   `https://github.com/AlmostGreenz/personal-site`, commit, push — the live
   site updates.

Config (canonical site URL for share buttons, LinkedIn URL, tag colours,
featured film) lives at the top of `build.py`.

### Adding a Font Awesome icon

The deployed `fontawesome-webfont.woff2` is subset to only the icons in use
(17 glyphs, ~2 KiB). To add one:

1. Use the `fa-*` class in a template and add its codepoint rule to `bold.css`:
   `.fa-<name>:before { content: "\fXXX"; }` (code from the FA 4.7 cheatsheet).
2. Run `python3 assets/fontsrc/subset-fa.py` — it audits every `fa-*` class in
   the templates/JS and fails loudly if one has no CSS glyph definition.
3. Rebuild with `python3 build.py`.

### Image pipeline

- Put source images in `source/static/images/` (video posters in
  `video-thumbs/`), reference them from `posts.json`.
- The build generates local WebP derivatives and 152px gallery thumbnails,
  computes intrinsic dimensions (kills image CLS), and emits `<picture>`
  markup. Any `<img>` with dimension attributes needs `height: auto`
  wherever CSS changes its width, or the height hint wins and distorts it.

### Dark mode

Toggled from the navbar (moon/sun), persisted in `localStorage`
(`rbg-theme`); first visit follows the OS preference, and a pre-paint head
script avoids a theme flash. The standalone VisualsAplenty doc pages stay
light-only.

## Deploying to GitHub Pages

The repo already exists (`AlmostGreenz/personal-site`, Pages serves `/docs`).
Deploying is: extract the latest build zip over the repo working copy,
commit, push. Always ship builds under a unique timestamped filename —
re-using a name serves stale bytes from attachment caches.

## Custom domain (ryanbgreen.ca)

The build already prepares everything:

- `docs/CNAME` is generated from the repo-root `CNAME` file (currently
  `www.ryanbgreen.ca`) — GitHub Pages picks it up automatically.
- `SITE_URL` in `build.py` is the canonical URL used for share links.

DNS setup (in Cloudflare's DNS panel — not the registrar):

- `www` → CNAME → `AlmostGreenz.github.io`
- apex (`@`) → A records → `185.199.108.153`, `185.199.109.153`,
  `185.199.110.153`, `185.199.111.153` (GitHub redirects apex → www)

On the Cloudflare proxy (orange cloud vs DNS-only gray cloud): the standing
recommendation is DNS-only, because GitHub Pages provisions and auto-renews
the HTTPS certificate itself and the proxy can break its renewal checks —
the site keeps working until the cert expires, then HTTPS breaks with no
warning. The tradeoff for proxying is Cloudflare's CDN/WAF/analytics in
front of the site. No final call made; nothing to change at WHC as long as
the nameservers already point at Cloudflare.

Then: repo Settings → Pages → Custom domain → `www.ryanbgreen.ca`,
wait for the certificate (~15 min), and tick Enforce HTTPS.

To make the apex canonical instead, change the repo-root `CNAME` and
`SITE_URL` to the bare domain and rebuild.
